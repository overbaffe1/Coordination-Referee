# Метрики и итоговый скор

Скорер: [`evaluation/evaluate.py`](../evaluation/evaluate.py),
определения метрик: [`evaluation/metrics.py`](../evaluation/metrics.py).

```bash
python evaluation/evaluate.py \
    --pred predictions.csv \
    --truth organizer/ground_truth.csv \
    --split public
```

## Итоговый скор

```
score = 0.50 · Macro F1
      + 0.25 · Robustness F1
      + 0.15 · Success F1
      + 0.10 · fault_turn_hit@2
```

Публичный лидерборд считается на public-подмножестве (2 000 ранов), финальный
— на private (2 000 ранов). Обе части перемешаны в одном `test.csv`, и по
`run_id` их различить нельзя.

## 1. Macro F1 (вес 0.50)

Невзвешенное среднее F1 по 7 классам `label`. Все классы равны, поэтому
редкие сбои стоят столько же, сколько `clean` (28 % данных).

## 2. Robustness F1 (вес 0.25)

Тот же Macro F1, но только на подмножестве ранов со сдвигом распределения
(≈ 33 % теста: длинные траектории, большие команды, редкие топологии, другой
домен и другой язык формулировок). Метрика наказывает решения, которые
переобучились на поверхностные признаки обучающей выборки.

Флаг `shifted` участникам не сообщается — определить срез самостоятельно
нельзя, но можно к нему готовиться (см. «Как поднять Robustness» ниже).

## 3. Success F1 (вес 0.15)

Бинарный F1 по классу `success = 1` (цель достигнута). Метка не выводится
однозначно ни из класса сбоя, ни из наличия финального сообщения.

## 4. fault_turn_hit@2 (вес 0.10, бонус)

Доля **действительно сбойных** ранов (`label_true ≠ clean`), для которых
одновременно:

* класс предсказан верно (`label_pred == label_true`), и
* `|fault_turn_pred − fault_turn_true| ≤ 2`.

Локализацию нельзя «фармить» отдельно от классификации: **если класс предсказан
неверно, попадание в ход не засчитывается**, даже если номер хода точный. Для
`clean` следует предсказывать `fault_turn = -1`; на метрику это не влияет, но
это часть контракта формата.

## Диагностика (в лидерборд не входит, печатается скорером)

* `in-domain F1` — Macro F1 на несдвинутой части;
* `worst topology group` — минимальный Macro F1 среди топологий;
* `per-class F1` — по каждому классу.

## Референсные значения baseline

| Метрика | public | private |
|---|---|---|
| Macro F1 | 0.741 | 0.759 |
| Robustness F1 | 0.706 | 0.679 |
| Success F1 | 0.853 | 0.849 |
| fault_turn_hit@2 | 0.361 | 0.372 |
| **Итоговый скор** | **0.712** | **0.713** |

Baseline обучается и предсказывает за ~1.5 минуты на 4 vCPU.

## Ориентиры

| Стратегия | Macro F1 | Итоговый скор (public) |
|---|---|---|
| всё `clean` | 0.06 | 0.05 |
| случайный класс | ≈ 0.13 | ≈ 0.11 |
| reference baseline (122 признака, LightGBM) | 0.741 | **0.712** |
| baseline + TF-IDF по текстам и последовательности типов событий | 0.769 | **0.738** |

Последняя строка — замер организатора: те же признаки плюс 50 000 TF-IDF-фич,
LightGBM на 900 деревьев, ~11 минут на 4 vCPU. Даёт +2.6 пункта к скору, но
`fault_turn_hit@2` при этом не двигается вовсе (0.376 против 0.357), потому
что локализация остаётся правилами. Это и есть главный незакрытый резерв
задачи: обучаемый per-turn ранжировщик стоит до +4 пунктов итогового скора
сам по себе.

## Как поднять Robustness F1

1. Нормируйте признаки на длину рана и число агентов — сдвинутые раны длиннее.
2. Не полагайтесь на конкретные формулировки: в сдвинутой части другой
   словарь. Работают структурные признаки (граф, учёт доставок, состояние).
3. Валидируйтесь на самом сложном срезе train: `mesh` / `blackboard`,
   длинные раны, домен `compliance_audit`, раны с потерянной телеметрией.
4. Аугментация: удаляйте `intent`/`refs`, обрезайте тексты, удлиняйте траектории —
   тренируйте модель на деградированных копиях.
